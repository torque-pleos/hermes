# Hermes — 화물 기사용 운행 점검 & 경로 강수 레이더 코파일럿

## 제출 안내

### ① 앱 이름 · 한 줄 소개

**Hermes** — 내비 경로의 경유지·도착지마다 **도착하는 시각에 비가 오는지**를 강수 레이더 이동 예측, 기상청 단기예보, 주변 차량의 와이퍼 관측으로 알려 주는 화물 기사용 차량 앱.

시연 영상: [docs/demo/hermes_demo.mp4](docs/demo/hermes_demo.mp4)

### ② 실행 방법

Pleos Connect 에뮬레이터를 켠 뒤 APK를 설치하고 실행합니다.

```bash
adb install -r apk/정건우_Hermes_release.apk
adb shell am start -n com.zigae.hermes/.MainActivity
```

에뮬레이터를 여러 대 띄웠다면 `adb -s emulator-5554 install ...`처럼 시리얼을 붙입니다. 앱 목록의 **Hermes** 아이콘으로도 실행할 수 있습니다.

소스에서 빌드하려면 JDK 17이 필요합니다. 빌드 결과는 `app/build/outputs/apk/release/app-release.apk`입니다.

```bash
cp secrets.properties.example secrets.properties   # 키는 비워 둬도 빌드됨
./gradlew assembleRelease
```

| 차량 공유 | **차량 공유** 탭에서 "내 와이퍼 관측 공유" 스위치를 켜면 와이퍼 상태를 1분마다 올립니다. **"시연: 경로 앞에 비 관측 차량 만들기"** 버튼은 경로 상류에 비를 보는 가상 차량 5대를 만들어, 브리핑·경로 예보가 차량 관측으로 바뀌는 모습을 보여 줍니다. 가상 차량은 10분 뒤 자동으로 지워집니다. 서버 설정 없이 빌드하면 "공유 서버가 설정되지 않았습니다"로 표시합니다 |

| 주행 화면 | 기어를 Drive로 바꾸면 주행 중 화면(입력·스크롤 없는 3줄 요약)으로 자동 전환됩니다. 정차 상태에서는 **진단** 탭의 "주행 화면 미리보기"로 볼 수 있습니다 |

curl -X PUT "http://127.0.0.1:8088/vehicle/body?front_wiper=High"   # Off | Auto | Low | High
curl -X PUT "http://127.0.0.1:8088/vehicle/gear?gear=Drive"         # Park | Reverse | Neutral | Drive

| 사용 가능 ✅ | 사용 불가 ❌ (준비 중/미제공) |

## 1. 문제 정의 (Pain Points)

현장 인터뷰에서 "업무용으로 필요하다"는 의견 확인 → 아래 가설을 추가 검증 필요.

| 대상 | Pain Point | 현재 대응 |
| --- | --- | --- |
| 카고/윙바디 기사 | 상하차 지점 도착 시 비 → 방수포 작업 지연, 화물(종이·가전·시멘트·농산물) 손상 | 폰 날씨 앱을 수시 확인, 감에 의존 |
| 상하차 작업 | 지금 상차할지, 비구름이 지나갈 때까지 기다릴지 판단 어려움 | 하늘 보고 판단 |
| 관제 담당자 | 기상으로 인한 지연을 사후에야 인지 → 화주 대응 늦음, 지연 위약금 분쟁 | 전화로 기사에게 확인 |
| 운송사 | 운행 전 점검이 형식적(수기 체크리스트) → 정비 누락·사고 | 종이 점검표 |

## 2. 핵심 기능

### F1. 운행 전 자동 점검 (DVIR 자동화)
- 시동 후 Vehicle State로 점검 항목 자동 수집 → "이상 없음 / 확인 필요" 요약.
  - 경고등(Telltales), 타이어 저압, 엔진오일·브레이크액·변속기오일 레벨, 워셔액 부족, 연료/배터리 잔량, 누적 주행거리.
- 자동 확인 불가 항목(적재 고정, 방수포 등)만 기사가 **정차 중 화면에서 체크**.
- 점검 결과는 서버(관제)로 전송 → 점검 이력 보관.

### F2. 강수 레이더 엔진 (RainViewer + 자체 이동 예측) ★핵심 기술
- RainViewer 과거 2시간 레이더(10분 간격 13프레임)를 서버에서 수집.
- 프레임 간 **비구름 이동 벡터를 직접 계산(광류/블록 매칭)** → 향후 30~60분 강수 위치 외삽.
  - RainViewer는 2026-01부터 예측(nowcast)을 제공하지 않으므로 **예측을 자체 구현** — 기술 활용성 포인트.
- 결과: 격자별 "N분 후 강수 강도" 맵.

### F3. 경유지(상하차 지점) 도착 시각 강수 타임라인
- NaviHelper로 경유지 목록 + 각 지점 ETA 획득 → F2 예측과 **도착 시각 기준** 매칭.
- 주행 중: "다음 하차지 도착 14:20 · 비 예상" 수준의 **짧은 화면 알림 + 알림음** (음성 없음).
- 우회 필요 시 정차 중/확인 후 `requestReRoute()` / `changeRouteOption()`.

### F4. 레이더 × 와이퍼 교차 검증 ★차별화
- `registerWiperState()`로 와이퍼 작동 상태 + NaviHelper 위치 수집.
- 레이더 예측과 비교:
  - 레이더 비 ○ / 와이퍼 ○ → 예측 신뢰도 상향
  - **레이더 비 × / 와이퍼 ○ → 레이더 사각(국지성·저고도 비)으로 판단, 실측 지도에 반영**
- 같은 운송사 차량들이 동일 노선을 반복 운행 → 고객사 1곳만으로도 데이터 밀도 확보.

### F5. 상하차·출발 타이밍 추천 (정차 중)
- 상하차 대기 중 화면에 레이더 애니메이션 + "비구름이 20분 후 도착 — **지금 상차하세요**" / "15분 후 비 그침 — 대기 권장".
- 정차 중이라 화면 UX 제약 없음.

### F6. 관제 대시보드 + 기상 지연 증빙 (B2B 판매 포인트)
- 차량별 위치·점검 상태·와이퍼 실측을 지도에 표시, 기상 지연 예상 차량 자동 감지 → 화주 사전 통보.
- **기상 지연 증빙 리포트**: "해당 시각·구간 레이더 강수 + 와이퍼 작동 기록" → 지연 위약금 분쟁 근거.

## 3. 사용 시나리오 (데모 스토리)

1. 06:00 시동 → "운행 전 점검: 타이어 공기압 경고 1건" → 적재 고정 체크.
2. 관제가 배차한 3개 하차지가 내비 경유지로 설정됨.
3. 주행 중 "2번째 하차지 10:40 도착 · 비 예상" 알림.
4. 와이퍼 작동 감지(레이더엔 비 없음) → 관제 지도에 "레이더 사각 강수" 표시 → 관제가 화주에 지연 사전 통보.
5. 하차지 도착(정차) → 레이더 화면 "비구름 15분 후 통과 — 대기 권장".
6. 운행 종료 → 기상 지연 증빙 리포트 자동 생성.

> 데모: Virtual Console로 와이퍼·타이어·기어(P↔D)를 시나리오대로 조작 + 실제 과거 강수 사례 레이더 프레임 재생.

| --- | --- | --- |

| 외부 (상용화) | 기상청 레이더 합성영상·초단기강수예측 (공공데이터) | 상용화 시 RainViewer 대체 |

## 5. 아키텍처 개요

```
[차량 앱 (Pleos Connect)]
  ├─ Vehicle State → 점검 데이터, 와이퍼 상태
  ├─ NaviHelper    → 경유지/ETA/현재 위치
  ├─ 주행 중: 짧은 화면 알림 + 알림음 / 정차 중: 레이더·점검 화면
  └─ HTTPS ─────────────┐
                        ▼
[Hermes 서버]
  ├─ 레이더 수집기: RainViewer 10분 주기 (상용: 기상청)
  ├─ 이동 예측: 프레임 간 이동 벡터 → 30~60분 외삽
  ├─ 경유지 × ETA × 예측 매칭
  ├─ 와이퍼 실측 집계 + 레이더 교차 검증
  └─ 증빙 리포트 생성
                        ▼
[관제 웹 대시보드] (데모는 목업)
```

## 7. 사업 모델 & 지표

- **과금**: 운송사 대상 차량당 월 구독(SaaS). 관제 대시보드·증빙 리포트는 상위 플랜.
- **확장**: 차량이 늘수록 와이퍼 실측이 촘촘해져 예보 향상 → Pleos 데이터 정책 안에서 지자체·도로공사와 도로 기상 협력. 기존 관제(TMS)에 "기상 모듈"로 연동.
- **도입 순서**: Pleos 탑재 배송·화물 차량부터, 상용 트럭에 Pleos가 들어가는 시점에 맞춰 카고·윙바디로 확대.
- **파일럿**: 같은 노선을 반복하는 운송사 3곳(약 100대)으로 노선별 차량 밀도를 먼저 확보(와이퍼 공유 효과 확보). 12개월 월 활성 차량 1,000대.
- **데이터 소스 전환**: 데모는 RainViewer(개인·교육용), **상용화 시 기상청 공공데이터**로 교체.
- **지표**: 등록 차량 수, 운행 대비 앱 활성률, 점검 완료율, 지연 사전 통보 건수, 고객사 연간 유지율(목표 85% 이상).

| Android 표준 TTS 사용 불가 (에뮬레이터 확인 완료) | 하 | 텍스트 알림 + 알림음으로 확정. 실차에서 다를 수 있으나 의존하지 않음 |
| 주행 중 화면 알림의 주의 분산 기준 | 중 | 짧은 텍스트·아이콘만, 레이더 지도는 정차 시에만 |
| NaviHelper 경로 전체 좌표 제공 여부 | 중 | 경유지 단위 매칭으로 F3 성립 |

**현장 추가 검증 질문**
- 비 때문에 실제 손해 본 사례(위약금·파손·재작업)? 빈도?
- 상하차 타이밍을 날씨 때문에 조정한 경험?
- 비용 지불 주체(기사/운송사/화주)? 지불 의향 금액?
- 가장 문제 되는 화물·차종?

## 9. MVP 범위 (공모전 제출)

- [x] 개발 골격 + SDK 진단 화면 (Vehicle State · NaviHelper 연결 확인)

- [ ] F1 운행 전 자동 점검 (Vehicle State)
- [x] F2 강수 레이더 엔진 (RainViewer 수집 + 이동 예측) — 진단 화면 연동, hindcast로 지속성 대비 개선 확인 (`docs/verification/`)

- [ ] F5 상하차 타이밍 추천 화면 (정차 시)
