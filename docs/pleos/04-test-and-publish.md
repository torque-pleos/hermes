## 1. 앱 테스트

### 1.1 폼 팩터 테스트 (FormFactorConsole + Host Display Bridge)

출처: https://document.pleos.ai/docs/pleos-only/app-test-guide/form-factor-test-guide

**개요**: 실행 중인 Pleos Connect Emulator에 가상 디스플레이(`DISPLAY2`)를 생성하고, 테스트할 앱을 그 디스플레이에서 실행합니다. 에뮬레이터 내 FormFactorConsole 앱에서 디스플레이 종류(Display preset)와 방향(Orientation)을 바꿔 가며 화면 표시를 검증합니다.

#### 준비물

- Android Studio, Android SDK Platform-Tools (`adb`)
- Go 1.22 이상
- 테스트할 앱이 설치된 Pleos Connect Emulator (AVD)
- 포트 `8095`, `8096` 사용 가능 환경

> 주의: 가상 디스플레이는 Android Emulator를 **별도 창**으로 실행할 때만 표시됩니다. Android Studio의 Running Devices 도구 창에 내장(embedded)하거나 Headless 모드로 실행하지 마세요.

#### 단계

1. **AVD 설정 및 실행**
   - System Image 추가/AVD 생성은 AVD 실행 가이드(`/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator`) 참고.
   - 연결 확인: `adb devices`
   - 여러 기기 연결 시 이후 명령의 `<SERIAL>`에 대상 시리얼(예: `emulator-5554`) 지정.
   - AVD 이름 확인: `adb emu avd name` → 예: `Pleos_Connect_v2.0` / `OK`
2. **Host Display Bridge 실행** (호스트의 FormFactorConsole ↔ Emulator 사이에서 가상 디스플레이 생성/제거 요청 중계)
   - `host-display-bridge.zip` 다운로드: https://nexus-playground.pleos.ai/repository/raw-releases/host-display-bridge/1.0.0/host-display-bridge.zip
   - 압축 해제 후 `host-display-bridge` 디렉터리에서 실행:
     ```bash
     go run . --avd "Pleos Connect v2.0"   # <AVD_NAME> 자리에 확인한 이름
     ```
   - 정상 로그: `ConnectWebConsole host display bridge listening on http://127.0.0.1:8096`, `Emulator gRPC target: 127.0.0.1:8554 (AVD: ...)`
   - 테스트가 끝날 때까지 이 터미널을 종료하지 않습니다.
   - 팁: Bridge가 AVD를 못 찾으면 AVD 완전 부팅 여부와 `--avd` 이름을 확인. 여러 AVD 실행 중이면 테스트 대상 외 AVD를 종료 후 재실행 권장.
3. **FormFactorConsole 접속**
   - 에뮬레이터에서 FormFactorConsole 앱 실행.
   - 상단에 `UNAVAILABLE` → Bridge 실행 여부 확인 후 **Refresh**.
   - 상단에 `DISCONNECTED` + "DISPLAY2가 없습니다." → 테스트 준비 완료 상태.
4. **폼 팩터 테스트**
   1. **Display preset**에서 폼 팩터 선택
   2. **Orientation**에서 `Portrait` 또는 `Landscape` 선택
   3. **테스트 화면 크기**에 표시된 dp, DPI, px 값 확인
   4. **가상 디스플레이 생성** 선택 (예: 12.9인치 Portrait, 14.6인치 Landscape)
   5. 새로 열린 `DISPLAY2` 창에서 앱 목록 확인. 자동으로 안 열리면 **앱 목록 실행**
   6. 확인 항목
      - 화면 요소가 잘리거나 겹치지 않는지
      - 텍스트·이미지·아이콘 크기와 정렬이 적절한지
      - 가로/세로 방향에 맞게 레이아웃이 배치되는지
      - 터치와 화면 전환이 정상 동작하는지
   7. 다른 폼 팩터 테스트: **가상 디스플레이 제거** 후 1~6 반복
   > 주의: 가상 디스플레이 제거 시 해당 디스플레이의 앱은 강제 종료됩니다. 테스트 데이터는 먼저 저장하세요.
5. **테스트 종료**
   1. FormFactorConsole에서 **가상 디스플레이 제거**
   2. Bridge 터미널에서 `Ctrl+C`
   3. ADB 포트 포워딩 제거: `adb forward --remove tcp:8095`

이 테스트는 심사 항목 "디스플레이 호환성"(레터박스 금지, 호환성 모드 금지, 해상도 전환 시 상태 유지, 기능 패리티)에 대한 사전 검증 수단입니다(4.2절 참조).

### 1.2 Virtual Console (Emulation Controls)

출처: https://document.pleos.ai/docs/pleos-only/app-test-guide/virtual-console-guide

**개요**: Pleos Connect Virtual Console의 **Emulation Controls**로 차량 상태/이벤트를 도메인별로 설정하여, 차량 상태 변화에 따른 앱 동작을 검증합니다.

사전 조건: Pleos Connect Virtual Console 셋업 가이드(`/docs/connect/guide/getting-started/application-development/use-vehicle-emulator`)에 따라 Emulator 실행 및 Virtual Console 접속.

1. Virtual Console에서 **Emulation Controls** 열기
2. 왼쪽 목록에서 Domain 선택 또는 검색창에서 카드 이름 검색
3. 카드에 차량 영역 선택 항목이 있으면 테스트할 영역 선택
4. 버튼/목록/슬라이더로 상태·값 변경
5. Emulator와 테스트 중인 앱에서 변경 결과 확인

## 2. 앱 등록 관련 가이드

### 2.1 앱 보안 가이드 (심사 미준수 시 통과 불가 가능)

출처: https://document.pleos.ai/docs/pleos-only/app-registration-guide/app-security-guide

문서는 이 가이드를 "단순 권고를 넘어 필수 기준"으로 규정하며, 미준수 시 심사 통과가 불가할 수 있다고 명시합니다. 아래에서 **[필수]**는 문서 표현이 "~해야 합니다", **[권장]**은 "~권장합니다"인 항목입니다.

#### 민감 데이터 관리 (PII, 금융정보, 민감 차량 데이터, 인증 토큰, 비밀 API 키, 암호화 키)
- [필수] 기기 저장 민감정보는 위치 무관 암호화 (내/외부 저장소, 캐시, SQLite, `SharedPreferences`). 내부 저장소 샌드박스 + 앱 수준 암호화. 임시 파일/사본에도 평문 금지.
- [필수] 디버깅 로그에 민감정보 기록 금지. 출시 전 로그 출력 비활성화 또는 마스킹.
- [권장] 민감정보 캐시 미저장. 필요 시 [필수] 암호화. 목적 종료된 캐시/임시파일 삭제 [권장].
- [권장] 자동 백업 비활성화. (Pleos Connect의 non-GAS AAOS 환경에서는 Google 자동 백업이 동작하지 않지만, 타 Android 환경 동시 제공을 고려). 백업 사용 시 민감 파일 제외.
- [권장] 민감정보는 앱 전용 내부 저장소. 외부 저장소 사용 시 [필수] 암호화.
- [필수] URL 경로/쿼리에 인증 토큰·세션·비밀번호 포함 금지 → `Authorization` 헤더 등 사용.

#### 안전한 암호화 사용
- [권장] 검증된 표준 알고리즘. 서명/무결성에 MD5, SHA-1 대신 SHA-256 등.
- [권장] AES-GCM 등 기밀성+무결성 모드. ECB 모드 회피.
- [권장] 표준 패딩 (예: RSA는 SHA-256 기반 OAEP). AES-GCM은 블록 패딩 불필요.
- [권장] IV 길이/생성 조건 준수. AES-GCM에서 동일 키로 IV/nonce 재사용 금지.
- [권장] 키/IV 생성에 암호학적으로 안전한 난수 생성기 사용.
- [필수] 암호화 키는 Android Keystore 등으로 보호. 소스/리소스/설정 파일 하드코딩 금지, 데이터와 함께 평문 저장 금지.

#### 안전한 통신
- [필수] 외부 통신은 HTTPS 등 암호화 프로토콜. 그 외 방식도 민감정보 평문 노출 금지.
- [필수] TLS 최소 1.2 이상 (1.3 권장). SSL, TLS 1.0/1.1로 연결되지 않도록 구성.
- [권장] 검증된 Cipher Suite (특히 TLS 1.2 사용 시 구성 검토).
- [필수] 신뢰할 수 있는 서버와만 통신. 악성/무관 서버 통신 금지.
- [필수] 서버 원격 명령 실행 기능은 출처·유효성·무결성 검증, 실행 범위 제한.

#### 컴포넌트 및 권한 관리
- [필수] 기능에 필요한 권한만 요청(최소 권한). 멀티 플랫폼 앱도 Pleos Connect 기준으로 관리.
- [필수] 외부 호출 불필요한 `Activity`, `Service`, `BroadcastReceiver`, `ContentProvider` 비노출(`exported` 제한).
- [필수] 민감정보 전달 시 수신 대상 명시. 암시적 브로드캐스트로 민감정보 전달 금지.
- [필수] 민감 데이터/보호 기능 컴포넌트는 호출자 인증 상태 + 접근 권한 모두 확인 후 허용.
- [필수] WebView 로컬 파일 접근은 필요 범위로 제한, 불필요 시 비활성화.
- [권장] 외부 전달 URI/파일 경로 검증·정규화.

#### 안전한 개발 및 배포
- [필수] Pleos가 공식 제공·허용한 API만 사용. 미허가 API 포함 금지.
- [필수] 차량 API는 앱 기능과 직접 관련된 범위에서만 사용.
- [필수] 인증 토큰·비밀 키 하드코딩 금지.
- [권장] 서버 IP 하드코딩 대신 도메인 등 관리 가능한 방식.
- [권장] 네이티브 라이브러리에 RELRO, Stack Canary, NX 비트 적용.
- [권장] SDK/라이브러리 취약점 주기 점검 및 패치 버전 유지.
- [필수] **배포용 앱은 정식 배포용 서명 인증서 사용 (테스트/디버그 인증서 금지)**.
- [필수] **최종 배포 앱에서 앱 디버깅(`debuggable`), 디버그 빌드 설정, WebView 원격 디버깅 비활성화**.

#### 브라우저 및 WebView
- WebView 앱: 위 통신·민감데이터·디버깅·로컬자원·접근제어 원칙 동일 적용. 로드 콘텐츠/이동 가능 사이트 범위 제한, JavaScript 및 JS 브리지는 필요할 때만 [권장].
- 웹브라우저 앱 추가 요구사항:
  - [필수] 신뢰할 수 있고 보안 업데이트가 지원되는 엔진만 등록 가능. 알려진 중요 취약점은 조치 버전 적용.
  - [권장] 악성/피싱 사이트 접근 제한 기능.
  - [필수] HTTPS 지원 사이트는 HTTPS로 연결. HTTP 전용 사이트 접속 시 위험 경고.
  - [필수] 서버 인증서 신뢰 체인·유효기간·호스트명 검증. 인증서 오류 무시 금지.
  - [필수] SOP/CORS 정상 적용, 임의 완화·우회 금지.
  - [필수] CSP Level 2 이상 지원 및 사이트 CSP 적용. 앱 자체 웹 콘텐츠엔 CSP 적용 [권장].
  - [필수] HTML/JS 처리 시 브라우저 검증·필터링·보안 기능 정상 적용.
  - [필수] 프로세스 격리/샌드박스 유지.
  - [필수] 최종 배포 앱에서 개발자 모드, 임의 프록시 설정 변경, 확장 프로그램 설치 기능 비활성화.
  - [필수] 파일 다운로드 기능 제한.

> 참고: 코드 난독화(ProGuard/R8)는 이 가이드에 항목으로 존재하지 않습니다.

### 2.2 앱 태그 표기 가이드

출처: https://document.pleos.ai/docs/pleos-only/app-registration-guide/app-tagging-guide

적용 대상: App Market/Console에 등록되며, **앱 타이틀 원문이 외국어이고 한국어 타이틀을 병행 또는 대체 표기**하는 앱.

- **영문 태그 필수**: 공식 타이틀이 외국어(예: 영어)면 한국어로 노출되더라도 원문(영문) 앱명을 반드시 태그로 추가.
- **영문 태그 표기 원칙**: 공식 앱명과 동일하게. 임의 축약/변형 불가.
- **한국어 태그(선택)**: 검색·인지 향상을 위해 추가 가능.
- **복수 언어 앱명**: 각 언어 공식 명칭 태그 추가 가능하되 영문 태그는 반드시 포함.
- 예: 공식명 `Sport` / 노출 타이틀 "스포츠" → 필수 태그 `Sport`, 선택 태그 "스포츠", "운동" 등.
- 태그는 최대 20개까지 입력 가능 (출처: 앱 심사 제출 가이드).
- **반려 사유**: 기준 미준수 시 반려 또는 수정 요청. 태그 누락/오표기 확인 시 앱 수정 요구.

### 2.3 앱 버전 관리 정책

출처: https://document.pleos.ai/docs/pleos-only/app-registration-guide/app-version-management-policy

- 배포 또는 심사 요청 시 **반드시 앱 버전 변경**.
- 기능 수정, 버그 수정, 설정 변경 등 앱에 영향을 주는 모든 변경은 버전 업데이트로 관리.
- 버전 미변경 시 변경 이력 확인 불가 → **심사 미진행 또는 반려**.
- 심사 요청 전 버전 정보가 정상 업데이트되었는지 확인.
- 참고: 문서는 "앱 버전"이라고만 표현하며 `versionCode`/`versionName` 각각의 규칙은 구분하여 명시하지 않습니다. Console 제출 항목에는 "버전명"(App Market 비노출)이 있습니다.

### 2.4 앱 업데이트 가이드 (인앱 업데이트 시퀀스 구현 의무)

출처: https://document.pleos.ai/docs/pleos-only/app-registration-guide/app-update-guide

**Pleos App Market은 자동 업데이트를 지원하지 않습니다.** 사용자가 직접 업데이트할 수 있도록 앱에서 업데이트 시퀀스를 제공해야 합니다.

#### 프로세스 (버전 확인 → 안내 팝업 → 앱 마켓 이동 → 업데이트 실행)

1. 앱 실행 시 최신 버전 여부 확인 — **개발사 구현**
2. 최신이 아니면 안내 팝업: `최신 버전이 존재합니다. 업데이트를 위해 페이지를 이동할까요? (Yes, No)` — **개발사 구현**
3. Yes → 앱 상세 페이지로 이동: `market://detail?package={패키지명}` — **개발사 구현**
4. 앱 마켓이 로그인 여부 확인 — **앱 마켓 제공**
   - 미로그인: 로그인 창 → 완료 후 마지막 사용 페이지 또는 앱 마켓 홈 이동, 업데이트 프로세스 종료
   - 로그인: 앱 상세 페이지 → 사용자가 **[업데이트]** 버튼 → 업데이트 진행
5. No → 업데이트 미진행. 개발사 정책에 따라 앱 사용 유지 또는 종료 — **개발사 구현**
6. 1에서 최신 버전이면 앱 실행 유지, 프로세스 종료

| 항목 | 개발사 구현 | 앱 마켓 제공 |
| --- | --- | --- |
| 버전 체크 | O | X (SDK 제공은 차후 고려) |
| 업데이트 안내 메시지 출력 | O | X |
| Yes 선택 시 이동 경로 제공 | O | X |
| 앱 상세 페이지 이동 시 로그인 확인/처리 | X | O |
| No 선택 시 조치 | O | X |

> 주의: 문서 원문의 딥링크는 `market://detail?package=` (단수형 `detail`)로 표기되어 있습니다. 표기 그대로 옮겼습니다.

## 3. 배포: 앱 심사 제출 (전체 흐름)

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-submission-guide

Pleos App Market에 차세대 인포테인먼트용 앱을 유통하려면 심사를 통과해야 합니다. 심사 신청 창구는 **Pleos App Market Console** (https://appmarket.pleos.ai/console/) 입니다.

### 3.1 단계별 흐름

1. **개발/테스트**: 1장(폼 팩터 테스트, Virtual Console)과 4장 체크리스트로 자체 검증
2. **보안 점검**: 2.1 앱 보안 가이드 준수, 멀웨어/바이러스/악성코드 미포함 확인
3. **버전 변경**: 2.3 정책에 따라 앱 버전 갱신
4. **인앱 업데이트 시퀀스 구현**: 2.4
5. **연령 등급 취득**: IARC 심의를 거쳐 등급 분류를 받고 증적 확보 (게임 등은 국가별 별도 심의, 예: 한국 게임물관리위원회)
6. **증빙 서류 준비**: 법률/규제 허용 증빙, 지적재산권, 정부기관, 웹 앱 도메인 등록, 의료기관, 성인 게임 GRAC 등 (4.4절, 5장 H)
7. **심사용 계정/서버 준비**: 모든 기능 접근 가능한 실사용자 계정, 외부 서버 구성요소 사전 활성화
8. **Console에서 앱 추가 및 제출 항목 입력** (3.2절)
9. **심사 노트 작성**: 설명이 필요한 기능 주석 + 기능 사용 설명서 첨부 (최대 60MB)
10. **심사 요청** → 심사팀이 필요 시 고객지원 연락처로 문의(법률 증빙, 파일, 하드웨어 이상 등)
11. **심사 통과 후 관리**: 지속 업데이트, 샘플링 모니터링/재심사 대상 (3.4절)

> 심사 소요 기간, 심사 상태값(진행 단계 명칭), 결과 통보 방식은 문서에 명시되어 있지 않습니다.

### 3.2 심사 제출 전 준비 사항 (문서 원문 정리)

- **개발자 정보 최신화**: 개발자(개발사) 정보 정확성 확인. 연락처는 심사팀이 언제든 연락 가능해야 함.
- **기능 이상 테스트**: 실행 불가, 크래시, 성능 저하, 버그, 이미지 깨짐, 해상도 늘어짐 없는지. 과도한 성능 점유(과부하, 배터리 소모 증가)는 차량 성능 및 안전과 직결. 성능 기준은 "성능 및 리소스 효율을 고려한 설계"(`/docs/pleos-only/vehicle-app-planning-guide/performance-resource-mgmt`)의 메모리·CPU·배터리 항목 참조.
- **보안성 확인**: 보안 취약점, 멀웨어·바이러스·악성코드 여부.
- **정보/메타데이터 확인**: 앱 명칭·버전명·카테고리 / 출시 국가·연령 등급·접근 권한·개인정보 처리 여부 / 패키지 파일·아이콘·스크린샷 / 이용약관·처리방침 등.
- **심사용 정보 제공**: 모든 기능·콘텐츠 접근이 활성화된 계정. 추가 요소 필요 시 심사팀이 요청 가능.
- **운영 요소 사전 활성화**: 외부 서버 연결 앱은 심사 중 즉시 연결 가능하도록.
- **운전자 안전 설계**: "주행 안전을 고려한 설계"(`/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline`) 확인.
- **출시 국가 법률·규제 준수**: 서비스/판매·홍보 제품(식약품, 의료기기, 서비스 등)의 출시 국가 허용 여부 확인. **규제 허용 증빙 제출 요구**.
- **연령 등급 적정성**: IARC 연계 심의. IARC 등급 증적 제출. 설정 등급보다 높은 수위 콘텐츠 확인 시 심사 거부.
- **심사 노트**: 설명 필요 기능 주석 + 기능 사용 설명서 첨부.

### 3.3 Console 제출 항목 (필수/선택/조건부)

| 카테고리 | 항목 | 필수 여부 | 규격/설명 |
| --- | --- | --- | --- |
| 앱 식별 정보 | 앱 관리명 | 필수 | 관리용 이름, App Market 비노출 |
| 앱 식별 정보 | 버전명 | 필수 | 앱 버전, App Market 비노출 |
| 기본 정보 | 국가/지역 설정 | 필수 | 출시 국가/지역 선택 |
| 기본 정보 | 패키지 파일 | 필수 | **APK 형식, 최대 600MB** (등록정보 가이드: 사용자가 다운로드할 압축된 최대 파일 크기가 600MB보다 작아야 함) |
| 기본 정보 | 대상 플랫폼 | 필수 | `Connect` 또는 `InfoLINK` |
| 기본 정보 | 카테고리 | 필수 | 가장 적합한 카테고리 (부적합 시 임의 변경 가능) |
| 기본 정보 | 연령 등급 | 필수 | 콘텐츠에 적절한 등급 |
| 기본 정보 | 개인정보 처리 | 필수 | 처리(수집·이용·파기·생성·연계·전송 등)하는 모든 개인정보 선택/입력 |
| 기본 정보 | 위치정보 활용 | 필수 | GPS, 지도, 사용자 위치 등 활용 시 선택 |
| 기본 정보 | 앱 접근 권한 | 필수 | 접근 기능 선택/입력 (카메라, 저장공간, 마이크, GPS, 전화, 연락처 등) |
| 기본 정보 | SDK 추가 권한 | 필수 | 권한 신청 필요한 SDK 사용 시 **My Project > 프로젝트 정보 > 프로젝트 ID** 입력 |
| 기본 정보 | 광고성 정보 | 필수 | 푸시 알림/SMS로 광고성 정보 전송 여부 |
| 언어별 정보 | 앱 이름 | 필수 | 출시 국가/지역별 모든 언어. **30자(영문 기준) 이하** (등록정보 가이드) |
| 언어별 정보 | 개인정보처리방침 | 필수 | URL. 국가/지역별 언어로 모두 확인 가능해야 함. 앱 전용 방침이 없으면 회사 공통 방침 가능 |
| 언어별 정보 | 위치정보 서비스 이용약관 및 기타 | 조건부 필수 | URL. (1) 기본 정보에서 '위치정보'/'GPS' 선택 또는 위치정보 활용 '활용함' 선택 시 필수, (2) 추가 처리방침/약관이 있으면 추가 작성 |
| 언어별 정보 | 간단한 설명 | 필수 | 앱 목록에서 앱 이름 아래 한 줄 설명, 모든 언어 |
| 언어별 정보 | 자세한 설명 | 필수 | 모든 언어 |
| 언어별 정보 | 태그 | 선택 | 검색 키워드, **최대 20개**, 태그 표기 가이드 준수 |
| 언어별 정보 | 앱 아이콘 | 필수 | **PNG 또는 JPEG, 최대 1MB, 512 x 512 px** |
| 언어별 정보 | IVI 스크린샷 | 필수 | **PNG 또는 JPEG, 1장당 최대 8MB, 최소 2장~최대 8장**, 해상도 규격: **2560 x 1380 px / 1700 x 1212 px / 840 x 1212 px** (아래 주석 참조) |
| 언어별 정보 | 출시 노트 | 필수 | 출시 노트 입력 |
| 고객 지원 정보 | 웹사이트 / 이메일 / 전화번호 | 1개 이상 필수 | 국가/지역별 언어로 확인 가능해야 함 |
| 심사 요청 정보 | 심사 노트 | 선택 | 심사 참고 사항, **파일 첨부 최대 60MB** |

> 스크린샷 규격 주석: 앱 심사 제출 가이드 표에는 세 번째 규격이 `840 x 121 px`로, 등록정보 심사 가이드에는 `840 x 1212 px`로 기재되어 있습니다. 문서 간 불일치이며 `840 x 1212`가 오기 수정본일 가능성이 높으나 Console에서 최종 확인이 필요합니다. 최소 2장 조건은 등록정보 가이드에 있습니다. 스크린샷은 업로드 순서대로 슬라이드되며, 예시로 "기능 사용 전 / 사용 후 / 앱 고유 기능 화면"이 제시됩니다.

### 3.4 심사 통과 후 업데이트 관리

- 심사 통과 후에도 품질·서비스 상태 유지를 위해 지속적으로 업데이트·관리해야 함.
- App Market은 주기적으로 앱을 **샘플링 모니터링**, 부적합 앱 재심사 및 필터링.
- **재심사 대상 예**: 심각한 오류/손상 보고 앱, 장기간 업데이트 없이 방치된 앱, 다수 신고 앱.
- 재심사 결과 등록 기준 미달 시 App Market에서 **제외** 가능.
- 업데이트 제출 시 버전 변경 필수(2.3), 사용자 측 업데이트는 인앱 시퀀스로 유도(2.4).

## 4. 앱 심사 가이드라인 (App Review Guidelines)

출처(개요): https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/

App Market은 운전자·탑승자 안전을 최우선으로, **운전자 주의 분산 요소**와 **사이버보안 위협 요소**를 심사에서 중점 검증합니다. 차량 운행 안전에 위험 가능성이 있다고 판단되면 어떤 경우에도 거부될 수 있으며, 가이드 전반을 준수해도 추가 위험 요소가 있으면 거부될 수 있습니다. 메타데이터를 악용해 사용자를 속이는 경우 **즉시 제외 및 영구 제재** 가능.

5대 심사 영역: 콘텐츠 안전성 / 앱 기능 및 성능 안정성 / 운전자 주의 분산 요소 최소화 / App Market 등록정보 / 사용자 개인정보 및 보안

### 4.1 콘텐츠 안전성

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-content-safety

- 미디어 콘텐츠 포함 앱은 서비스 국가/지역 심의 필요. 미디어 중계 플랫폼(OTT, 웹툰 등)·UGC 앱은 **필터링 기능 + 신고 채널** 필수.
- 예외: 경각심 고취, 안전한 차량 이용 안내 등 공익 목적 또는 ESDA(교육·과학·다큐멘터리·예술) 목적이면 허가 가능.
- 금지 콘텐츠
  - 안전 저해: 음주 운전, 과속, 신호 위반 권유·조장·홍보·미화. 주류 광고는 현지 광고법 준수 + 음주 운전 위험 경고 포함 필수.
  - 선정적: 현지 법규상 불허 수준의 노출, 포르노, 성적 만족 서비스, 성매매 알선/홍보 → 거부.
  - 폭력적: 과도한 폭행·유혈·테러 및 조장·미화, 과도한 욕설·폭언.
  - 위험한 내용: 자살·자해 조장 거부, 아동 안전 위협 엄중 금지, **아동이 차량 밖으로 신체 일부를 내밀도록 유도하는 콘텐츠 거부**.
  - 불법: 범죄 조장/알선, 테러·약물·무기·인신매매 등 권유·조장·홍보.
  - 사행성: 실제 금전 거래 도박, 불법 도박 조장·홍보·경로 제공.
  - 차별: 인종·종교·성별 등 차별 조장·미화.
  - 민감: 재난·사고·전쟁·갈등·전염병 등을 시사하거나 이를 통해 이익을 얻는 유해 내용.
  - 승인되지 않은 물품: 미승인 식/약품, 건강/의료기구, 처방전 없는 처방약 판매·구매 용이화.
- 미성년자 및 아동 보호
  - 아동 학대·착취·성적 목적 콘텐츠(성착취, 인신매매, 그루밍 등) 엄격 금지.
  - 아동 관심을 유도하면서 성인용 주제(과도한 폭력·피·신체 훼손, 유해·위험 활동, 노출·성적 내용) 포함 금지.
  - **인증 없이 볼 수 있는 화면, 미리보기, 썸네일, 인앱 스크린샷, 상품 사진은 '전체 이용가' 콘텐츠만**.
- 연령 등급: 등급 조사 설문에 정직하게 답변. 부여 등급에 부적절한 콘텐츠 확인 시 제한 및 신고 가능. 영화·음악·게임 등은 현지 요건 준수.
- 기타
  - 지적재산권 침해 금지(상표, 저작물, 특허, 위조품 판매·홍보). 신고 시 **다운로드 경로 우선 차단 → 기한 내 법적 정당성 소명 실패 시 앱/개발자 영구 제외** 가능. 권리 보유자는 권리 사실을 사전 또는 요청 시 제출.
  - UGC/AI 생성 콘텐츠 앱: 부적절 콘텐츠 필터링 + 개발자 신고 기능 필수.
  - 블록체인: **암호화폐 채굴 앱 거부** (하드웨어 손상·성능 저하·안전 문제).
  - 확률형 아이템(루트 박스): 구입 전 항목 유형별 수령 확률 공개.

### 4.2 앱 기능 및 성능 안정성

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-functionality-performance-stability

- **완성도**
  - 설치/삭제 오류 금지 (인증 키 누락으로 미설치, 설치 후 파일 누락, 삭제 후 아이콘/잔여 파일).
  - 실행 오류 금지 (강제 종료, 하드웨어 재시작).
  - 기능 사용 오류 금지 (화면 멈춤, 기능 미동작, 터치/상호작용 미인식).
  - 미디어 출력 정상 (사운드 끊김, 그래픽 깨짐 금지).
  - 제출 앱 = 실제 서비스 앱. 테스트용 더미 데이터·임시 파일·임시 콘텐츠 금지.
  - UI 요소 왜곡·흐림·모자이크 없는 표시.
  - 디스플레이 컷아웃, edge-to-edge 인셋, 가장자리 디스플레이, 소프트웨어 키보드, 시스템 표시줄 포함 시 기기 안전 영역 준수 (UI 세이프티 존, 입력 방법, 자막, 탐색 메뉴 고려).
- **기능 및 성능**
  - 선택한 카테고리를 벗어나는 기능 또는 서비스와 다른 카테고리 선택 시 거부 가능.
  - 기능 미동작/오동작 금지.
  - 심각한 성능 저하(스터터링, 프레임 저하, 화면 끊김) 금지.
  - 시스템 성능 저하 금지: **입력 후 차량 시스템 응답 시간 0.25초 이하** (터치 → 터치 효과 애니메이션 발생까지).
  - **앱 실행 10초 이내, 콘텐츠 로드 10초 이내, 특정 버튼 반응 2초 이내** (반응 = 화면 전환, 기능 동작, 상태 변화). 2초 내 불가 시 UI로 동작 중임을 표시.
  - 백그라운드 복귀 시 마지막 상태 복원 (수 시간 이상 미사용 시에만 기본 상태 시작 가능).
- **하드웨어/소프트웨어 손상**: 손상 및 과점유로 인한 성능 저하 금지. 기기 재시작이나 핵심 기능과 무관한 시스템 설정 변경을 제안/요구 금지.
- **SDK·API 사용 심사**: 차량 상태 변경/운전 안전 영향 SDK·API는 별도 기준.
  - Vehicle SDK API 사용 시 필요한 퍼미션을 앱에 선언.
  - Vehicle SDK 퍼미션은 **Pleos App Market과 사전 협의·승인된 경우에만** 선언 가능.
  - **승인되지 않은 퍼미션 선언 앱은 심사 통과 불가**.
- **디스플레이 호환성** (상세: Display Layout 가이드 `/docs/connect/guide/docs-design/getting-started/layout`)
  - 레터박스 없이 디스플레이 영역 최대한 채움 (미세 비율 보정을 위한 한 방향 레터박스만 허용 가능).
  - **호환성 모드 실행 금지**.
  - 해상도 전환 시 상태 손실·화면 이상 금지 (작업 내용 손실, 이미지 늘어짐, 앨리어싱/블러, 터치 영역-버튼 위치 불일치).
  - 모든 화면 상태에서 기능 패리티 유지 (버튼/기능 변경 금지, UI는 비율에 맞게 이동).

### 4.3 운전자 주의 분산 요소 최소화 설계

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-driver-distraction-elements

- Pleos Connect UI Design Guide(`/docs/connect/guide/docs-design/Introduction/intro`) 사전 확인 필수. 준수해도 추가 위험 판단 시 거부 가능.
- **미디어 앱(동영상, 게임, 브라우저 기능 보유 앱)**
  - 운전 중 실행·사용 불가, **정차 중에만 사용 가능**.
  - 운전 시작 시 사용 일시 중지 + **UI 숨김**. 운전 중 '일시 중지' 해제 불가.
  - 백그라운드 복귀 시 마지막 상태 복원 (수 분 내 복귀: 최대한 가깝게, 수 시간 이상: 마지막 또는 기본 상태).
  - 모든 미디어 항목에 한눈에 들어오는 제목·썸네일 제공. 제목/썸네일/미리보기에 부적절 내용 금지.
  - **헤드업 알림 게시 금지** (운전과 무관한 알림 사용 불가).
  - 동영상 앱은 **미디어 세션 통합**, 동시 다중 미디어 불가, 재생/일시정지/중지 명령 지원.
  - 브라우저 앱은 비밀번호·결제 정보 저장/액세스 허용 금지 (프로필 잠금으로 비밀번호 액세스 차단 가능 시 예외).
  - 비밀번호/결제 데이터 동기화 브라우저: 동기화 전 사용자 인증 메시지 표시 + 차량 화면에서 동기화 사실 고지.

### 4.4 Pleos App Market 등록정보

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-app-registration-info

- 기본 정보(이름, 설명, 개발자 이름, 아이콘, 이미지 등) 정확 입력.
- 부적절 내용 금지: 욕설·폭언·폭력·선정 묘사, 범죄/불법(약물, 테러) 묘사, **사실 확인이 힘든 App Market 실적·순위·매출**, **텍스트 이모티콘·반복 특수문자**.
- 제목/아이콘: 간결하게 대표 정보 전달. 타 앱과 유사·중복·오해 소지 금지. **제목 30자(영문 기준) 이하**.
- 서비스 대상 국가별 언어로 모든 메타데이터 제출.
- 카테고리: 가장 적합한 것 선택 (부적합 시 임의 변경).
- 아이콘: 앱 대표 내용, 규격 준수 (최대 1MB, 512x512, PNG/JPEG). 출력 상태 비교용 아이콘 이미지 제출.
- 스크린샷: 주요 기능 설명 최소 2장~최대 8장, 1장당 8MB, 2560x1380 / 1700x1212 / 840x1212, PNG/JPEG. **아이콘·이미지가 실제 앱과 다르면 거부**.
- 패키지: **APK**, 압축된 다운로드 크기 600MB 미만.
- 개인정보 처리 과정, 접근 권한, 위치정보, 광고성 정보 전송은 정직하게 설정. 개인정보처리방침 필수 (회사 공통 방침 가능). 위치정보 사용 시 '위치정보 이용약관 및 기타 정보 처리방침' 함께 제출.
- 로그인 필요 앱: 모든 접근 권한 가능한 계정 제출. **관리자 계정이 아닌 실사용자 기준 계정**, 게스트 가능해도 일반 사용자 계정, 웹 앱도 연결 페이지용 계정.
- **증빙 서류**
  - 국가/지역 공인 기관의 적법 권리·허가 증빙 (필요 시).
  - 타사 지적재산권(브랜드명, 웹사이트, 로고, 오디오/이미지 저작물) 사용 권리 증빙.
  - 정부/정부기관 대행 또는 허가 앱: 증명 서류 (해당 정부/기관이 제출).
  - 웹 앱 등 웹 페이지 연결 앱: **도메인 등록 증빙** (호스팅 업체 발급 도메인 등록 확인증).
  - 공인 의료기관 개발·제휴 배포 권한 증빙.
  - 대한민국 성인용 게임물(도박/카지노 요소, 선정적 내용): **GRAC 심의 등급 결과 및 증빙** (직접 부여 필수).

### 4.5 사용자 개인정보 및 보안

출처: https://document.pleos.ai/docs/pleos-only/distribute/app-review-guide/review-user-privacy-security

- 개인정보 정의: 개인 식별, 금융·결제, 인증 정보 등 및 결합 시 식별 가능한 모든 정보.
- 준수 사항
  - 접근 권한 최소화.
  - 법적 고지(수집 항목, 처리 목적, 보유 기간, 동의 거부 권리) + 명시적 동의 절차.
  - 수집 목적·보유 기간 구체 기재, 최소 처리, 목적 외 활용 금지.
  - 처리방침 공개, 열람청구권 등 이용자 권리 보장. 그 외 GDPR 등 국가별 법령 적용.
  - 위치정보 저장/이용 서비스: 국가 법규에 따른 등록/신고 확인 요청 가능, 미확인·허위 시 판매 중단 가능.
- 투명성: 앱 자체에서 수집 데이터 목록, 사용 방식, 공유 내용 명시.
- 동의: 개인정보 보호 법률 준수 증빙 또는 약관을 App Market에 제출 (위반·신고 시 증거로 사용). 아동 개인정보는 수집 전 법정대리인 고지 및 명시적 동의.
  - 동의/거부 UI는 명확해야 함.
  - **동의 버튼 외 행동(뒤로가기, 빈 공간 터치 등)을 동의로 간주 금지**.
  - 허가된 항목 데이터에만 접근.
- 보안
  - 보안 위협: 기기·프로그램·데이터 손상/교란/변조, 동의 없는 코드/프로그램 설치 → **즉시 거부 가능**.
  - 보안 우회: 시스템 보안 보호 기능 우회·무력화·손상 → **즉시 거부 가능**.
  - 사용자 데이터 무단 사용: 동의 없는 탈취·보관, 광고 활용, 제3자 전송 금지. 맞춤형 광고는 동의를 통해서만. 사용자가 철회 시 **즉시 활용 경로 차단 + 저장 데이터 삭제**. 불법·부적절 광고, 스팸, 반복 알람 앱은 제외 가능.
  - 악성행위: 바이러스, 스파이웨어, 트로이 목마, 애드웨어, 루팅 / 스팸, DDoS, 크립토재킹 / 피싱, 사기광고 금지.
